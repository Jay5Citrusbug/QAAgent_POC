## 5. Regression impact

This appears to be a fixed practice/demo site; changes are unlikely to be code changes from a dev team but rather intentional defect seeding for QA training. Regression impact is therefore about **detecting drift**: if any of the five documented defects gets silently 'fixed' or the layout changes, downstream training exercises depending on defect presence will break. The five defect-baseline missions (SM-001–005) double as regression-detection tripwires.

## 6. Smoke set

P0: SM-001 (Hoem typo), SM-002 (broken logo), SM-005 (cart icon a11y name), SM-007 (product card structure). These are the fastest, most stable, purely presence/text checks with no dependency on undefined interactive behavior — ideal for a smoke suite that must run on every build without ambiguity.

SM-003 and SM-004 (footer/hero typos) are P1 — same pattern but lower visibility risk.

## 7. Not worth automating yet

- Category filter click-behavior, Add to Cart behavior, carousel dot-click behavior: none of these have a stated expected outcome. Automating them now would require guessing behavior, producing false-defect risk. Better left as manual exploratory items until G-1/G-2/G-3 are answered.
- Footer Quick Links vs nav-link parity: ambiguous whether this is even a requirement (AM-2); not worth a mission until clarified.

## 8. Confidence

Moderate. The five explicitly stated defects are unambiguous and safe to automate as-is. Confidence is low for anything implying interactive/functional behavior (filtering, cart, carousel) since the requirement is purely structural/descriptive. Strengthening this would require either a walkthrough of the live app (to observe actual behavior) or direct answers from the requirement author on G-1, G-2, G-3, G-6.

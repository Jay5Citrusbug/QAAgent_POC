# Baseline — before the first agent run

The POC's KPI is:

> **Human QA effort required to reach a trustworthy feature-level smoke
> decision.**

As stated, that cannot be proven. These two numbers make it measurable, and both
must be captured **before** the first real agent run — afterwards, the manual
baseline is unrecoverable.

Fill this in by hand. It is five minutes of work and it is the difference
between proving the POC worked and asserting it.

---

## 2. Mission edit rate (capture every time, at Gate 1)

This is the number most likely to kill the approach quietly. Missions a human
must heavily rewrite are a net loss even when execution is free — the review
cost simply moves the work rather than removing it.

`npm run approve` records `review_minutes` and `edits_made` into each mission's
approval block, so this table can be rebuilt from git at any time.

long to review as mission 1, the Thinking Agent's prompt is not improving and
the bottleneck has moved to Gate 1.

## 3. Per-run execution cost

|---|---|---|---|---|---|---|---|
| | | | | | | | |

Gate 2 minutes matter as much as Gate 1. A run that produces four INCONCLUSIVE
results and forty minutes of human investigation has cost more than the manual
smoke it replaced.

## 4. Trust metrics

These decide whether anyone will actually use the system.

| Metric | Why it matters | Value |
|---|---|---|
| False defects reported | A single confident false defect costs more trust than ten INCONCLUSIVE results | |
| Classifier / human disagreement rate | How often the human overrides the proposed classification | |
| Missions needing a locator fix after a UI change | The real maintenance cost, and the thing that kills most automation | |
| Runs where evidence was insufficient to judge without re-running | Directly tests whether the evidence policy is good enough | |

---

## 5. The honest verdict

At the end of POC-1, answer in one sentence each:

1. Did total human QA minutes to a trustworthy smoke decision go **down**?
2. Would the QA Lead act on a PASS from this system without re-checking by hand?
3. Would they act on a FAIL without re-checking by hand?

If the answer to (1) is yes but (2) and (3) are no, the POC produced activity,
not leverage. That is a real outcome and worth reporting plainly — it says the
evidence and classification need work before scope grows, and expanding to more
projects at that point would multiply the problem rather than the benefit.
